Un salon de discussion où chaque client a son propre thread

Un serveur Java à sockets TCP : chaque client est servi par un thread dédié, et tous les messages sont diffusés dans le même ordre à tout le monde. Rejoignez le salon et regardez, à droite, les lignes du protocole circuler dans le serveur.

        Le protocole, ligne par ligne

        Une ligne de texte UTF-8 par message. Le premier champ donne le type, le texte libre est toujours le dernier champ : il peut donc contenir des « | ». Les clients console et les navigateurs reçoivent exactement les mêmes lignes.

        Ligne envoyée par le serveurQuand
        PSEUDOÀ la connexion, et après chaque pseudo refusé.
        OK|JackLe pseudo est accepté.
        ERREUR|Ce pseudonyme est déjà utilisé.Pseudo refusé, commande inconnue, destinataire introuvable.
        MSG|14:02:11|Jack|BonjourMessage public, envoyé à tous, expéditeur compris.
        HISTO|14:02:11|Jack|BonjourLes 20 derniers messages publics, envoyés à un nouvel arrivant.
        PRIVE|14:03:40|Sarah|Jack|Tu as fini ?Message privé, reçu seulement par Sarah et Jack.
        INFO|14:03:58|Youcef a rejoint la conversation.Arrivées, départs, réponses à /list et /help.
        USERS|Jack,Sarah,YoucefListe des connectés, à chaque arrivée ou départ.
        BYELe serveur ferme la connexion (après exit, ou à l'arrêt du serveur).

        Rejouer une session enregistrée sur le serveur Java

        Trois clients, onze étapes. Chaque flèche est une ligne réellement envoyée sur un socket.

        Qui travaille, et dans quel thread

        Le serveur n'utilise que la bibliothèque standard de Java. Chaque rôle tourne dans son propre thread, ce qui permet à un client lent de ne jamais bloquer les autres.

        main

        Serveur attend les connexions avec ServerSocket.accept() et confie chaque nouveau socket au pool.

        client-tcp-N

        Un ClientHandler par client console : choix du pseudo, puis lecture de ses lignes avec readLine(). Bloquer ici ne bloque que ce client.

        web-N

        La PasserelleWeb sert cette page et tient un flux SSE ouvert par navigateur : les lignes du protocole y sont poussées une à une.

        web-nettoyeur

        Toutes les 5 s, retire les navigateurs fermés sans prévenir (20 s pour se reconnecter).

        reception et envoi

        Côté client console : un thread affiche ce qui arrive du serveur, l'autre lit le clavier. On peut écrire et recevoir en même temps.

        Ce qui garantit un salon cohérent

        • Pseudo unique, même sous la course. La réservation est un ConcurrentHashMap.putIfAbsent atomique, sans tenir compte de la casse : sur 20 demandes simultanées du même pseudo, une seule réussit (testé).
        • Même ordre pour tout le monde. Toutes les diffusions passent par un seul verrou dans SalonDeChat : 30 clients qui écrivent au même instant reçoivent les 30 messages dans le même ordre (testé).
        • Aucun message perdu à l'arrivée. L'historique et l'activation d'un nouvel arrivant se font sous ce même verrou.
        • Départs toujours nettoyés. exit, terminal fermé ou réseau coupé : le bloc finally libère le pseudo et prévient les autres, une seule fois.
        • Accents intacts entre Windows et Linux. Les sockets sont lus et écrits explicitement en UTF-8.

        Lancer le vrai serveur sur votre machine

        Compiler puis démarrer (Java 11 ou plus), depuis la racine du projet :

        javac -encoding UTF-8 -d bin (Get-ChildItem -Recurse src -Filter *.java).FullName
java -cp bin chat.server.Serveur

        Ou double-cliquez sur LANCER_SERVEUR.bat : il compile, démarre le serveur et ouvre cette page sur http://localhost:8080.

        Rejoindre le même salon depuis un terminal :

        java -cp bin chat.client.Client
java -cp bin chat.client.Client 192.168.1.20 5000

        Les autres machines du réseau local peuvent ouvrir l'adresse affichée par le serveur.
